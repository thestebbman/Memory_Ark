DUAL-NODE ARCHITECTURE SPECIFICATION: RASPBERRY PI 5 CLUSTER


Deployment Model: Distributed Edge Cluster with Human-in-the-Loop (HITL) Verification.

NODE 0: Primary Ingestion & Processing (The Worker)
Core Function: Synchronous data capture and local model execution.

Audio Pipeline: Runs local, offline transcription algorithms to ingest raw audio streams (from video or direct microphone inputs) and convert them to plain text.

Text/Screen Pipeline: Monitors designated host-machine buffers or text streams to duplicate and log active typing.

GUI Output: Pushes all parsed strings to a shared, front-facing visual terminal. This satisfies the strict requirement that no background processing occurs without immediate visual display.

NODE 1: Telemetry & Validation (The Supervisor)
Core Function: Quality control, hardware oversight, and hot-standby redundancy.

Process Monitoring: Continuously pings Node 0 to track CPU utilization, thermal thresholds, and VRAM limits to ensure processing efficiency.

Data Validation: Audits the transcription output generated by Node 0. Scans for missing application labels, broken formatting, or logic gaps prior to human review.

Redundancy (Failover): Maintains a synchronized mirror of the file directory. If Node 0 crashes or overloads, Node 1 assumes the processing workload without dropping the session.

Standardized Evolution Protocol:
The dual-node system outputs its raw data to a standardized form on the visual terminal. When the human operator manually corrects an error, Node 1 logs the delta (the difference between the AI's output and the human's correction) as a training note, allowing the local architecture to map new linguistic variables over time.
